# 来源会话与封装差异

定位依据为 **2026-10-12 15:38 开始**的公众号双平台 API 会话，最终交付发生在 16:59 左右。先讨论 TikHub 和 Just One API，再试采 FDE，随后讨论为什么 Just One API 花了 4 元。

四项共同证据：

- 四个关键词，144 条原始搜索记录，去重后 102 篇。
- 7 篇已核验候选、25 条对照记录，21 条对照有有效读数、4 条补采失败。
- TikHub 50 次尝试、46 次成功、4 次失败，原账单核对为 USD 0.46。
- Just One API 12 次账号搜索，7 次 biz 匹配、5 次错配；2 次免费、10 次收费，历史实际 CNY 4。

这不是另一条“两篇精选、相邻十篇、中位数 289.5 和 516”的会话，也不是抖音工作流。公开仓库不附私人会话全文；来源缓存的文件内容指纹保存在精简样本中，用于维护者核对。

## 保留与修正

| 原隐含行为 | 本仓库处理 |
|---|---|
| 临时路径、临时脚本和个人 Key 来源 | 可配置运行目录、完整脚本、自备 Key，原凭证不复制 |
| 旧 config 写五篇，实际初始三篇 | 以真实执行口径三篇为准，补采规则单列 |
| 列表 create_time 被当作发布日期 | 保留旧数学口径，显式标为创建时间代理；不再承诺真实发布满七天 |
| 有效三篇之后四次失败补采 | 原失败保留用于重放；实时补采遇首次失败停止 |
| 账号搜索连续查十二个 | 默认关闭；可选质量探针单独授权、最多两次、无可靠质量证据即停 |
| 当时 USD 0.01 和 CNY 0.40 的价格 | 仅当历史记录；TikHub 每轮核价，Just One API 单独核实当前单价 |
| 失败、错误或缺失字段可能混入 | 只有成功且精确的统计参与计算；缓存和账本做哈希绑定 |
| 中文结论藏在会话里 | 写作标准、标题与正文差异、七篇摘要样稿随包提供 |
| 完整响应含全文和无关元数据 | 白名单保留可复算字段，删除全文、缓存 URL、debug、请求 ID、个人余额等 |

这些修正公开说明，避免把旧实现的错误或试探成本固化为默认要求。新的实时结果不保证恰好七篇，固定回放则必须严格匹配以上数值。
